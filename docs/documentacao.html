Visao Geral

O Carlesso Pilates Frontend e a interface administrativa do estudio. A aplicacao centraliza pacientes, prontuario, profissionais, planos, pagamentos, aulas, relatorios e usuarios administrativos.

Objetivo do produto

Apoiar a operacao do estudio com cadastros, acompanhamento clinico, controle financeiro basico, confirmacao de aulas e relatorios para tomada de decisao.

Publico de uso

Usuarios autenticados do estudio. Fluxos sensiveis como profissionais, relatorios e administracao sao restritos ao perfil ADMIN.

Estado atual

MVP funcional com dashboard, prontuario do paciente, autenticacao JWT, autorizacao por perfil, relatorios exportaveis e CRUD administrativo de usuarios.

Arquitetura

A arquitetura segue a organizacao padrao de uma SPA Angular moderna: componentes standalone carregados sob demanda, services tipados para integracao REST e uma camada global de seguranca HTTP.

Estrutura principal

  • src/app/core/models: contratos e DTOs usados pela UI.
  • src/app/core/services: integracao com endpoints REST.
  • src/app/core/guards: protecao de autenticacao e perfil.
  • src/app/pages: telas por dominio funcional.
  • src/app/shared: componentes e utilitarios reutilizaveis.
  • src/styles/_tokens.scss: tokens do Design System Carlesso.

Padroes tecnicos

  • Componentes standalone, sem NgModules.
  • Imports individuais de diretivas e pipes do Angular.
  • Metodos e textos de dominio em portugues.
  • Validacao defensiva de parametros numericos de rota.
  • Estados explicitos de loading, erro, vazio e salvamento.
  • URLs relativas para preservar portabilidade entre dev e Docker.

Fluxos Principais

Os fluxos abaixo explicam como a aplicacao se comporta nos caminhos mais relevantes de uso e integracao.

Autenticacao e requisicoes

  1. 1

    Usuario envia credenciais em POST /api/auth/login.

  2. 2

    AuthService armazena accessToken e currentUser no localStorage.

  3. 3

    authInterceptor adiciona Authorization: Bearer nas requisicoes protegidas.

  4. 4

    Resposta 401 so derruba a sessao quando indica token invalido ou expirado.

Prontuario do paciente

  1. 1

    Rotas recebem pacienteId e validam com utilitario compartilhado.

  2. 2

    Componentes carregam a identificacao do paciente antes da tela especifica.

  3. 3

    Services acessam endpoints dedicados de anamnese, avaliacao, sessoes, evolucoes, planos e reavaliacoes.

  4. 4

    Fluxos de alteracao usam confirmacao quando envolvem cancelar, suspender, encerrar ou excluir.

Seguranca e Controle de Acesso

A seguranca no frontend combina autenticacao JWT, guards de rota, exibicao condicional de navegacao e tratamento criterioso de respostas de erro.

Elemento Arquivo Responsabilidade
authGuard src/app/core/guards/auth.guard.ts Bloqueia rotas quando nao ha token e redireciona para /login.
roleGuard src/app/core/guards/role.guard.ts Permite rotas por perfil e envia usuarios sem permissao para /403.
authInterceptor src/app/core/interceptors/auth.interceptor.ts Inclui bearer token e executa logout apenas quando a API sinaliza token invalido ou expirado.
AuthService src/app/core/services/auth.service.ts Centraliza token, usuario logado, role atual, helpers de permissao e limpeza de sessao.

Execucao Local e Docker

O frontend usa URL relativa /api. Em desenvolvimento, o Angular CLI encaminha para http://localhost:8080; em container, o Nginx usa BACKEND_URL.

Desenvolvimento

Instale dependencias e suba o servidor do Angular CLI com proxy configurado.

npm install
npm start

A aplicacao fica disponivel em http://localhost:4200.

Container

A imagem faz build Angular em multi-stage e serve os arquivos estaticos com Nginx.

docker compose up --build

BACKEND_URL=http://api:8080 docker compose up --build

Testes e Qualidade

A suite usa Karma e Jasmine. A cobertura existente contempla rotas, app component, guards, interceptor, services e componentes de pagina.

Comando principal

npm test

Use para validar regressao de comportamento em componentes, services e guards.

Quando ampliar testes

  • Alteracoes em rotas e precedencia de parametros.
  • Mudancas em services ou contratos REST.
  • Fluxos com permissao, token, logout ou perfil.
  • Componentes compartilhados e validacoes de formulario.

Convencoes de Evolucao

Ao evoluir o projeto, mantenha a linguagem, os padroes de arquivo e a separacao de responsabilidades ja adotados no codigo.

Assunto Padrao atual Exemplo

Services providedIn: 'root', metodos em portugues e URLs relativas listar(), buscar(), inativar()
Estilos Preferir tokens semanticos a cores soltas var(--primary), var(--border-default)
